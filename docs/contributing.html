Project guide

Contributing & releases

Keep the adapter close to upstream json-render while preserving an Ember-first component API.

Development

Use Node.js and npm. Install dependencies, build the addon, and try it in an Ember app compatible with the package peer dependencies.

npm install
npm run build

Keep feature claims in the README and docs aligned with what the renderer implements. Changes to the core wire format should be coordinated with upstream json-render.

Prepare a release

  1. Make and review the code change.
  2. Add a Changesets note with npm run changeset. Choose patch for fixes, minor for compatible features, and major for breaking changes.
  3. Commit the generated file under .changeset/ with the code change and open a pull request.
  4. After merging, run npm run version-packages to apply the queued version and changelog updates. Review and commit those changes.
  5. Build and verify the package, then publish manually with npm run release when the release is approved and npm trusted publishing is configured.
Publishing is manualGitHub Pages deploys the docs only. There is no npm publish workflow; a maintainer initiates publishing from a trusted environment.

Changesets policy

Changesets are based on main and the package is configured for public npm release. Keep one changeset per user-visible package change so the changelog explains what consumers need to know.
